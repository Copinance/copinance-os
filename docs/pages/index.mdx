# Copinance OS

![](../images/copinance-os.gif)

**Copinance OS** is an open-source **financial research engine**: a Python library and CLI you can run, audit, and embed. The **Copinance** product is one application that can sit on top of it — this repo is not that product.

You get two modes of work: **repeatable, number-driven analysis** (same inputs → same structured outputs) and, when you want it, **natural-language research** where a model **uses the same data and calculators** to answer questions — not to guess prices or macro figures.

The product vision is in the [Manifesto](https://github.com/copinance/copinance-os/blob/main/MANIFESTO.md): research that meets people at their literacy level, with named uncertainty and traceable methodology.

## What this system is

| Idea | What it means |
|------|----------------|
| **Numbers first** | Prices, history, fundamentals, volatility context, macro series, and options analytics (**QuantLib**-based Greeks where applicable — including higher-order sensitivities when valid — plus deterministic **aggregate positioning**: GEX, vanna/charm, mispricing, pin risk, and related surface metrics) are produced by ordinary code paths you can test and inspect. The system favors **structured results** over free-form blobs so every run is auditable. |
| **AI as a narrator and researcher, not a calculator** | Language models **summarize, compare, and answer questions** by calling **tools** that pull or compute real data (markets, macro, filings when configured). The model is **not** the authority for quotes, Greeks, or economic prints—it **grounds** answers in what the tools return. You can plug in **Gemini**, **OpenAI**, **Anthropic**, or local **Ollama**. |
| **One pipeline for terminal and code** | Whether someone runs a command in the shell or your app calls the library, **the same orchestration path** runs the analysis. That keeps behavior consistent and avoids “CLI magic” that does not exist in code. |
| **A real command-line, not only a Python import** | After install, you use the **`copinance`** command for analysis, market lookups, profiles, and cache. You can also type a **research question directly** (no subcommand) for a broad, tool-assisted answer. Machine-readable output, token streaming, and optional prompt capture are available where documented in the [CLI reference](user-guide/cli). |
| **Swappable pieces** | Data sources, tools, and execution backends are treated as **replaceable components** behind stable interfaces, so you can extend the system without rewriting the core. |

## Capabilities at a glance

- **Audience-aware explanations** — Analysis can be tuned to **financial literacy** (from plain-language to technical). This is **context for wording**, not a login system; your product still owns user identity if you need it.
- **Curated follow-up questions** — After you render a quote, chain, regime card, or similar artifact, the library can suggest **Ask AI chips** grounded in that payload (`generate_curated_questions_use_case`). See [library guide](getting-started/library#curated-follow-up-questions) and [client integration](developer-guide/curated-questions-integration).
- **Two ways to run analysis** — **Fixed pipelines** (walk through defined steps every time) and **question-driven** runs (the model picks which data and analysis tools to use for your question). **Back-and-forth conversations** with memory are supported when you use the **Python library**, not as a single CLI session—see the [library guide](getting-started/library#multi-turn-question-driven-analysis).
- **Macro and regime in one place** — Broad economic and market-stress indicators (rates, credit, labor, housing, and more) sit alongside single-name and options work.
- **Shared caching** — Fetches used during CLI market commands and during analysis can **reuse the same cache**, so repeated work is cheaper. You can inspect and clear cache from the CLI.
- **Research-shaped output** — Successful runs can include a **standard report shape**: summary, metrics, and a methodology envelope (`specs` + `data_inputs`) so outputs read like research, not only raw JSON.
- **License** — Apache 2.0.

## Core concepts

Same ideas appear in the CLI, the library, and later pages. Names and types: [Analysis modes](user-guide/analysis-modes), [Using as a Library](getting-started/library), [Architecture](developer-guide/architecture).

| Concept | Meaning |
|---------|---------|
| **Layers** | **Data** brings markets/macro/filings in. **Domain** is deterministic meaning (indicators, jobs, reports). **Execution** runs a study end to end. **AI** narrates and picks tools; it does not replace pricing. **Interfaces** are the CLI here, and any HTTP/chat you build ([agent progress](developer-guide/agent-progress-client-integration)). |
| **Contracts** | Typed handoffs (quote, run result, methodology envelope) so outputs are reproducible. |
| **Profile** | Literacy and preferences for *wording*, not a login. Your product maps users to profiles. |
| **Scope and horizon** | Instrument vs market backdrop; short / mid / long lookbacks. |
| **How a run works** | `auto` (question → agent, else pipeline), deterministic-only, or question-driven-only. CLI is **one question per invocation**; multi-turn is library-only. |
| **What comes back** | Success/failure, structured `results`, often an `AnalysisReport` with `specs` + `data_inputs`. Front door: `ResearchOrchestrator.run_job`. |
| **Tools** | Same calculators as deterministic paths. Bundles: `PluginSpec`, optional entry points, package scan. |
| **Cache and config** | CLI uses `.copinance`; library is disk-free unless you inject storage/cache. Env vars change endpoints and keys, not what a ratio *is*. |

Extend via ports: [Extending](developer-guide/extending).
